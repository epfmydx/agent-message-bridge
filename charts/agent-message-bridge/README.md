# agent-message-bridge Helm chart

Installs the private bridge API, worker, and schema initialization job from one independently built image. The chart creates only these workloads and an internal `ClusterIP` Service; configure ingress separately if required.

Before installation, create an external PostgreSQL database dedicated to Agent Message Bridge, a Kubernetes Secret named by `existingEnvSecret`, and a config Secret named by `existingConfigSecret` with key `config.json`. The environment Secret provides `DATABASE_URL`, `BASE_URL`, `SESSION_SECRET`, and `ENCRYPTION_KEY`. Optional storage settings are `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, and `S3_SECRET_KEY`; optional delivery settings are `WEBHOOK_URL` and `WEBHOOK_TOKEN`. Add every credential variable referenced by both `participants[]` and `owners[]` in config. The initial config therefore also requires `AGENT_A_API_KEY`, `AGENT_B_PASSWORD_HASH` and `OWNER_PASSWORD_HASH`; owner references are not optional when owners are configured. Use a database URL reachable from the Pods, not the generated Compose service hostname or a workstation's loopback URL. The generated Compose `.env` contains host interpolation paths and is not a ready Kubernetes Secret; supply the shared application settings/credential references rather than copying it unchanged. The config file is mounted read-only at `/run/bridge/config.json` and sets bridge participants as documented by the source configuration contract.

Browser pages require a dedicated existing origin Secret referenced by `adminOrigin.secretName`/`secretKey` and the actual app-facing gateway addresses in `adminOrigin.trustedProxyCidrs`. The API alone receives these values. Keep the origin secret out of the shared environment Secret. Missing origin configuration leaves browser pages closed while machine APIs retain their own authentication. Configure Cloudflare to overwrite `X-Bridge-Origin`, preserve a public `CF-Connecting-IP` and forward a single HTTPS scheme through the trusted gateway. See the [origin guide](../../docs/operations/cloudflare.md) for the complete path and expected fail-closed `403`; health success alone does not enable sign-in. Keep the origin value out of worker/init env.

The initialization job also adds the browser membership/date indexes to existing databases using coordinated concurrent PostgreSQL builds. Use a schema-owner database role and allow initialization to complete.

The chart does not create Secrets, database resources, public ingress, or cloud storage. It disables service-account token mounting and runs containers as UID/GID 10001 with a read-only root filesystem and an empty `/tmp` volume. The API Service listens on port 8000 and readiness uses `/healthz`.

For immutable releases set `image.repository` and `image.digest`; a digest overrides the development tag. The source-only release workflow validates this chart without packaging or publishing an image or OCI chart. An operator supplies an image built in their own environment and may pin its digest.

For direct host processes use the separate [direct Python recipe](../../docs/operations/setup.md#direct-python-processes); the chart's `/run/bridge/config.json` path is correct inside its Pods. Let the pre-upgrade initialization hook complete. For a compatible stored-runtime rollback, use explicit context/namespace and `--no-hooks`; see [schema and recovery](../../docs/operations/setup.md#schema-and-recovery). No live install or rollback is implied by an offline render.
